Overview

SpecForge starts with an unstructured product idea and ends with a set of agent-ready documents.

The application guides the idea through clarification, a brief and document generation. The result is a specification, task list and agent instructions that can be reviewed, copied or downloaded together.

My work covered the full-stack application, the LLM integration and the streamed review experience.

Workflow

  1. 01

    Clarify

    Start from the raw product idea and clarify what needs to be specified.

  2. 02

    Brief

    Turn the clarified input into a structured brief for the generation pipeline.

  3. 03

    Generate

    Create spec.md, tasks.md and agents.md, with output streamed live using Server-Sent Events.

  4. 04

    Review & export

    Review the documents in tabs, copy them, regenerate an individual document, or download a zip with JSZip.

Engineering

A server-side LLM boundary

OpenRouter calls sit behind a server-side wrapper. The browser never receives the API key. Automatic fallback-model retry gives the pipeline another model path when a call fails.

Structured output, checked

Zod validates the model’s JSON output. Per-IP rate limiting adds a boundary around request volume. These are explicit application controls around the generation workflow.

Progress that stays visible

Server-Sent Events stream the generation to the interface. The tabbed viewer supports reviewing and regenerating individual documents instead of repeating the entire flow.

Documents that leave the app

Copy actions and a one-click zip download make the generated documents usable in the next step of development. Sentry is integrated for error tracking.

Limitations

The workflow supports clarification, streamed generation, document-level revision and export. It gives the idea a consistent structure and a practical handoff into development.

Valid JSON is a structural check, rather than a measure of a specification’s completeness. The review step remains important: requirements and tasks need to fit the intended product before they guide implementation.
